# Agent 团队协调

本参考文件只用于 `discipline_track=stem` 的项目，定义理工科路径中各 Agent 角色的职责、提示词要点和协调模式。不要读取或借用人文社科路径的 Agent 分工。

## 使用时机

- 当宿主确认支持并行 Agent，且材料包含 3 个及以上文件或跨越多个类别时，优先使用团队模式；宿主不支持或无法确认并行能力时使用 `serial`。
- 当材料极少（1–2 个同类文件）时，可在主流程中直接处理。
- 具体运行模式、阶段屏障、串行 fallback 和恢复规则由 [../../runtime/index.md](../../runtime/index.md) 与 [../../runtime/phase-barrier.md](../../runtime/phase-barrier.md) 决定；本文件只定义 `execution_strategy=team` 时的角色和协作细节。
- 所有输出文件结构以 [output-templates.md](output-templates.md) 为准。

## 协调原则：共享黑板产物

所有 Agent 都通过 `_analysis/` 下的明确文件交换信息，不依赖隐含上下文。主流程负责合并和裁决，子 Agent 不直接修改最终文件，除非它被明确分配了某个输出文件。

关键共享产物：

- `_analysis/questions/*.json`：每份真题的结构化题目片段。
- `_analysis/question-index.json`：主流程合并后的真题全集，是后续覆盖审计的唯一真题来源。
- `_analysis/question-index.md`：给用户和审查 Agent 阅读的人类版题目索引。
- `_analysis/coverage-audit.md`：逐题覆盖状态。
- `_analysis/exam-tutor-state.json`：当前项目状态和可恢复执行信息。

如果不同 Agent 对同一事实冲突，优先级是：真题原文 > 老师复习范围/课堂强调 > 讲义/PPT > 笔记 > 补充材料 > 模型常识。

## Phase 1-2：题目提取与证据分析分波

讲义数据量通常极大，而真题数据量小但最重要。采用严格分波策略：第一波只提取题目来源，父流程合并 `question-index` 后，第二波才以真题结果引导讲义、课件、笔记和补充材料分析。

### 第一波：题目来源优先

由于每份真题试卷都包含独立的考试信息，**每份真题、样题或复习题文件分配一个独立的 Question Agent** 进行深度分析，确保逐题提取不遗漏。第一波不处理讲义、课件、笔记或补充材料。

| 角色 | 输入来源 | 输出文件 |
|------|----------|----------|
| 真题分析 Agent | `materials/past-papers/2025-final.pdf` | `_analysis/past-paper-analysis-2025-final.md` + `_analysis/questions/2025-final.json` |
| 样题分析 Agent | `materials/past-papers/sample-midterm.pdf` | `_analysis/past-paper-analysis-sample-midterm.md` + `_analysis/questions/sample-midterm.json` |
| ... | ... | ... |

**真题拆分规则**：
- 每份真题试卷（每个独立的 PDF/文件）分配一个专属 Agent
- 这样确保每道题都被仔细提取，不会因为一个 Agent 处理过多试卷而遗漏细节
- 所有真题 Agent 并行运行，充分利用并行能力
- 输出文件名使用来源文件的稳定 `source_slug`，避免增量更新时因排序变化覆盖旧输出

### Phase 1.5：真题索引合并

等待第一波的题目分析全部完成后，父流程合并 `_analysis/questions/*.json`，生成 `_analysis/question-index.json`、`_analysis/question-index.md` 和高频考点/低置信度题目摘要。即使没有真题，也要写入空的 `question-index`，再进入第二波。

### 第二波：材料证据分析（真题引导）

等待 `question-index` 完成后启动。由于讲义内容通常非常丰富，**每个讲义文件分配一个独立的 Evidence Agent**，确保每份讲义都能得到充分的深度分析。课件/笔记和补充材料可按类别合并；如果单类材料很大，继续拆分。

| 角色 | 输入来源 | 输出文件 |
|------|----------|----------|
| 讲义分析 Agent | `materials/lectures/week-01.pdf` | `_analysis/lecture-analysis-week-01.md` |
| 讲义分析 Agent | `materials/lectures/week-02.pdf` | `_analysis/lecture-analysis-week-02.md` |
| ... | ... | ... |
| 课件/笔记分析 Agent | `materials/notes/` + PPT 文件 | `_analysis/slides-notes-analysis.md` |
| 补充材料分析 Agent | `materials/supplements/` | `_analysis/supplement-analysis.md` |

**拆分规则**：
- 每个讲义文件分配一个独立的 Agent，不再合并处理
- 讲义内容量大，合并处理容易导致分析深度不够、遗漏关键细节
- 所有第二波 Evidence Agent 在同一阶段内并行运行，充分利用并行能力

**真题引导**：每个讲义分析 Agent 的提示词中必须包含真题分析的高频考点排名，要求 Agent 优先深入分析与高频考点相关的章节，对低频或未出现在真题中的内容进行快速扫描而非深度分析。

### 真题分析 Agent

最重要的分析角色。每份试卷由一个专属 Agent 深度分析，确保每道题都被完整提取。

**提示词要点**：
- 读取该份真题文件（PDF 先调用 `$pdf` 如可用）
- 提取每道题的：完整题目文本（**必须逐字逐句从原文复制，包括所有数值、条件、子问题，不允许概括、缩写或用自己的话复述**）、年份、题号、子题标签、分值、考查知识点、题目类型、难度
- 如果 PDF 提取的文本不完整或有乱码，必须结合页面渲染逐字核对，确保题目文本与原件一致
- 对每道题进行初步的知识点标注（例如"本题考查条件概率和贝叶斯定理"），这些标注将在后续知识图谱阶段与正式知识点建立映射
- 标记分值分布规律和常见陷阱
- 输出高频考点排名表（此表将作为第二波讲义分析的优先级指引）
- 同时输出结构化 JSON 片段到 `_analysis/questions/`。JSON 中的题目 ID 必须稳定，后续所有知识点文件都引用这些 ID

**输出结构**：

```
# 真题深度分析 — [文件名]

## 概览
- 年份/学期：
- 考试类型：
- 总题目数：

## 逐题分析
#### 题 [编号]
- 完整题目文本（逐字复现，不得概括）：
- 分值：
- 考查知识点（初步标注）：
- 题目类型：
- 难度：

## 本卷高频考点排名
| 排名 | 知识点 | 出现次数 | 涉及题目 |

## 常见陷阱
```

JSON 片段结构遵循 [output-templates.md](output-templates.md) 中的 `_analysis/questions/<source-slug>.json` 模板。

**汇总阶段**：所有真题 Agent 完成后，主流程合并各 `past-paper-analysis-*.md` 和 `_analysis/questions/*.json`，生成统一的 `_analysis/question-index.json`、`_analysis/question-index.md` 和高频考点排名表供第二波讲义分析使用。同时建立"题目→知识点"的初步映射，在 Phase 3 知识图谱阶段正式确认。

### 真题索引合并

主流程执行，不交给并行 Agent。

1. 读取所有 `_analysis/questions/*.json`。
2. 检查题目 ID 是否重复；重复时按来源文件和题号重命名，并在 `notes` 中记录。
3. 检查是否有低置信度题目；低置信度题目进入索引，但在 `coverage-audit.md` 中标记风险。
4. 生成 `_analysis/question-index.json`，作为后续真题全集。
5. 生成 `_analysis/question-index.md`，按来源文件列出每道题，方便用户人工检查。
6. 生成合并后的高频考点排名，传给第二波讲义分析 Agent。

### 讲义/教材分析 Agent（每个子批次）

每个讲义文件由一个独立 Agent 深度分析，不再合并处理，确保分析深度。

**提示词要点**：
- 接收真题分析的高频考点排名作为优先级指引
- 对与高频考点相关的章节进行深度分析：提取核心概念、定义、定理、公式、完整推导和解题示例
- 对未出现在真题中的章节进行快速扫描：仅提取标题、核心定义和章节关系
- 识别教材强调的内容（加粗、框注、反复提及）
- 记录章节间的逻辑依赖关系
- 标注哪些内容与真题高频考点直接相关
- 为每个高收益知识点准备“教学素材包”，不要只列名称：
  - Motivation：该章节为什么引入这个概念，解决什么问题
  - 定义/符号：原文定义、符号约定、变量条件
  - 定理/公式：精确陈述、适用条件、证明或推导线索
  - 例题/练习：能支撑从零讲解的基础例子和考试例子
  - 易错点：讲义中的警告、条件限制、常见误读
  - 概念关系：与前置章节、后续章节和真题题型的连接

**输出结构**：

```
# 讲义/教材分析 — [文件名]

## 分析的文件
- 文件名：

## 与真题高频考点相关的深度分析
### [章节名]
- 关联的真题考点：
- 核心概念：
- 关键定义：
- 重要定理/公式：
- 解题示例：
- 教材强调内容：
- 从零教学素材包：
  - Motivation：
  - 定义/符号：
  - 推导线索：
  - 基础例子：
  - 易错点：
  - 与前后知识关系：

## 快速扫描的章节
### [章节名]
- 核心定义：
- 章节关系：

## 章节依赖关系

## 关键公式汇总
```

### 课件/笔记分析 Agent

**提示词要点**：
- 提取幻灯片标题层次和框架结构
- 识别老师的强调模式（反复提到、特别标注、明确说"这会考"）
- 提取演讲者备注中的高价值内容
- 从课堂笔记中提取疑难点解释和学习捷径
- 保留老师原始措辞
- 特别提取适合写入 KP 文件的直觉解释、类比、课堂例子、易错提醒和复习提示；这些内容优先进入 Writer Agent 的上下文

**输出结构**：

```
# 课件与笔记分析

## PPT 框架
### [幻灯片组名称]
- 主题结构：
- 老师强调要点：
- 演讲者备注亮点：

## 课堂笔记精华
- 疑难点解释：
- 学习捷径：
- 口头强调：

## 老师关键措辞
```

### 补充材料分析 Agent

**提示词要点**：
- 提取额外的解题示例和练习题
- 整理公式表和速查内容
- 标记与主教材不同的解释角度

## Phase 3：汇总与知识图谱构建

所有分析 Agent 完成后，主流程执行汇总：

1. 读取 `_analysis/` 下所有分析结果
2. 读取 `_analysis/question-index.json`，把它作为真题全集，建立统一的"题目→知识点"映射表，确保每道真题都被至少一个知识点覆盖
3. 合并所有讲义分析 Agent 的输出（`lecture-analysis-*.md`），解决跨文件的重复和衔接
4. 交叉比对各 Agent 发现的知识点，合并重复项
5. 利用讲义分析的章节依赖关系确定学习顺序
6. 利用课件/笔记分析识别老师重点强调的内容
7. 生成 `knowledgepointslist.md`
8. 生成 `_analysis/coverage-audit.md`，列出每道题的覆盖 KP、解析位置和风险

### 整合规则

- 当不同 Agent 对同一概念有不同命名时，优先使用老师在课件中的措辞
- 当真题考点不在讲义分析中时，仍作为考试关键主题纳入
- 当讲义内容从未在真题中出现时，降低其优先级但不删除
- 讲义深度分析中标记为"与真题高频考点相关"的内容优先纳入知识图谱

## Phase 4：并行知识点文件生成

### 分配策略

- **每个知识点分配一个独立的撰写 Agent**，确保每个知识点都能获得充分的深度和篇幅
- 父流程先按 `knowledgepointslist.md` 的前置依赖生成稳定的前置摘要，并把 KP 拆成依赖层
- 同一依赖层的撰写 Agent 可以并行运行；下一层必须等待上一层完成，除非父流程已经提供足够完整的前置摘要

### 撰写 Agent 上下文

每个撰写 Agent 必须获得：
1. 完整的 `knowledgepointslist.md`（含 Mermaid 关系图）
2. 该知识点相关的材料分析摘录（从 `_analysis/` 提取）
3. 该知识点负责的题目 ID 列表，以及来自 `_analysis/question-index.json` 的完整题目文本（Agent 需在文件中完成每道题的完整解析，并归纳题型通用解题流程）
4. **该知识点的前置知识点文件**（如已生成），或由父流程预先生成的前置知识点核心要点摘要，用于回扣和闭环
5. 从讲义、课件、笔记和真题分析中抽取的“教学素材包”：Motivation、定义/符号、定理/公式、推导线索、基础例子、易错点、老师原话、材料位置
6. 知识点文件输出模板（含 SKILL.md Step 7 的质量要求）

### 撰写 Agent 核心指令

- 遵循 output-templates.md 中的知识点文件模板
- 文件名必须以序号开头，如 `KP-01-topic-name.md`，文件内一级标题也带序号
- 核心教学部分是最重要的部分，投入最多篇幅；把主题写成一堂从零开始的迷你课，而不是材料摘要或检查表
- 默认按详细标准写。即使学习者时间紧，也只在文中标注“先学/后学”，不要省略核心解释、基础案例、推导、例题和易错点
- "直觉"部分必须用最通俗的大白话，配合至少一个具体的生活化例子或课程场景，让学习者先理解“它在解决什么问题”
- 严格遵循"问题/Motivation → 概念关系图 → 直觉 → 定义/符号 → 基础案例 → 推导/原理 → 例题 → 题型流程 → 真题解析"教学顺序
- 积极使用 `> [!tip] 学习指南`、`> [!note] 直觉理解`、`> [!warning] 易错点`、`> [!example] 例题`、`> [!tip] 考前速记`
- 使用 Mermaid 图展示概念依赖、判别流程、证明结构或题型分支；不要把复杂关系写成一长串 bullet
- 每个新符号第一次出现时必须解释含义、取值范围、适用条件和常见误用
- 对每个关键公式说明：为什么这样写、从哪里来、什么时候能用、什么时候不能用
- **题型通用解题流程**：对该知识点下的真题进行归类，提炼每种题型的步骤化解题模板，让学习者遇到同类题时能直接套用
- **真题完整解析**：每道真题先给出整体解题思路（考什么、用什么方法、为什么），然后逐步解题。解题重点在推理和方法选择，繁重计算使用代码工具完成。综合题归入主要知识点并交叉引用
- **题目 ID 不可丢失**：每个真题解析标题必须包含题目 ID，例如 `### Q-2025-final-01 2025 Final 题 1`，便于审查 Agent 做覆盖检查
- 深度扎根于材料，而非通用解释
- **回扣前置知识点**：讲解后置知识点时，必须在合适的位置主动回扣前置知识点的核心概念，形成闭环。例如在讲解"贝叶斯定理"时回扣"条件概率"的定义和直觉，让学习者感受到知识的串联和递进。具体做法：
  - 在"问题"部分说明"为什么学了 KP-XX 之后，自然会遇到这个新问题"
  - 在"直觉"部分回扣前置知识点的类比，在其基础上延伸
  - 在"严格推导"部分指出哪些步骤直接使用了前置知识点的公式或结论
  - 在文件末尾的"链接"部分明确列出前后依赖关系
- 如果材料分析摘录不足以支撑从零教学，不要生成薄文件；先回到相关讲义/课件/笔记补充教学素材包，或在文件中明确标注缺失证据并补写必要的前置解释
- 禁止保留模板占位符、空标题或只有一两行的核心小节；写完后按 output-templates.md 的“薄文档判定”自检并扩展
- 保存到 `knowledge-points/` 目录

## Phase 5：质量审查

所有知识点文件生成后，生成审查 Agent 进行全面检查。

### 检查项

1. **真题覆盖完整性**：每道真题是否在至少一个知识点文件中被分析
2. **材料引用准确性**：引用的材料内容是否真实存在
3. **教学逻辑连贯性**：核心教学部分是否遵循规定顺序
4. **前置依赖一致性**：依赖关系是否无矛盾、无循环
5. **深度充分性**：基础主题是否有足够深度
6. **跨文件一致性**：不同文件对同一概念的描述是否一致
7. **真题解析完整性**：每个知识点文件中是否包含该知识点下所有真题的完整解析，是否归纳了题型通用解题流程
8. **索引一致性**：所有被解析的题目 ID 是否都存在于 `_analysis/question-index.json`，是否存在索引中的题目没有出现在任何 KP 文件中
9. **从零可学性**：是否有学习指南、Motivation、直觉解释、基础案例、符号表、推导说明、易错点、考前速记和快速自检；公式是否逐符号解释
10. **结构化理解辅助**：是否在概念依赖、判别流程、证明结构或题型分支处使用 Mermaid 图；callout 是否帮助学习而非装饰
11. **薄文档风险**：是否存在大量短 bullet、空泛摘要、只有定义没有例子、只有真题没有基础铺垫、基础 KP 只做速查表等问题

### 审查输出

保存到 `_analysis/quality-review.md`，并同步更新 `_analysis/coverage-audit.md`：

```
# 质量审查报告

## 总体评估
- 知识点文件总数：
- 通过审查数：
- 需要修正数：

## 需要修正的问题
### 问题 [N]
- 严重程度：高 / 中 / 低
- 涉及文件：
- 问题描述：
- 修正建议：

## 真题覆盖验证
| 真题 | 覆盖状态 | 对应知识点文件 |

## 索引一致性
- question-index 总题数：
- KP 文件中出现的题目 ID：
- 索引中未出现但被 KP 引用的题目 ID：
- 索引中存在但未被任何 KP 解析的题目 ID：

## 深度不足的文件
- 文件：
- 缺失的教学环节：
- 是否影响从零学习：
- 必须补写的内容：
```
