# 人文社科路径 Agent 团队协调

本文件只用于 `discipline_track=humanities-social-sciences` 的项目。不要复用理工科路径的公式、推导、计算题 Agent 职责。

## 使用时机

- 当宿主确认支持并行 Agent，且材料包含 3 个及以上文件或跨越多个类别时，优先使用团队模式。
- 当材料极少时，可串行执行，但仍遵守本路径输出模板。
- 所有共享产物写入 `_analysis/`；最终模板以 [output-templates.md](output-templates.md) 为准。

## 协调原则

人文社科项目的共享黑板不仅记录“题目”，还要记录课程话语和证据：

- `_analysis/questions/*.json`：真题、样题或复习题的结构化片段。
- `_analysis/question-index.json`：题目全集。
- `_analysis/lecture-analysis-*.md`：课件、讲义、阅读材料中的讲次顺序、核心问题、概念、作者、文本、争议和案例。
- `_analysis/slides-notes-analysis.md`：课堂强调、老师措辞、笔记中的分析提示。
- `_analysis/supplement-analysis.md`：补充案例、政策、事件、阅读材料。
- `_analysis/coverage-audit.md`：题目覆盖和材料重点覆盖。

如果课件质量高、真题较少或不存在，团队进入 **lecture-first 模式**。所有 Agent 应保留 lecture 线索，并做跨讲合并和考试化概括。

### Subagent 格式约束原则

本节只放松 subagent 的读入呈现方式和中间输出格式，不改变 Phase 分工、读取优先级、写入边界或最终 KP 模板。

- 父流程给 subagent 的输入不要预先压成固定表格、少数字段或逐项填空卡片。可以给任务目标、材料路径、必要摘要和材料摘录，但不要用格式裁掉材料中的语气、论证顺序、案例细节和争议层次。
- `_analysis/*-analysis*.md` 是中间分析文件，不需要套用最终 `knowledge-points/` 的模板，也不强制固定小节、表格列名、字段顺序或每项都填满。
- Evidence Agent 可以根据材料本身选择长文分析、分层笔记、讲次脉络、主题索引、概念关系、案例库或综合备忘录。重点是信息充分、出处清楚、关系讲明白。
- 必要的机器可读产物仍保持结构化，例如 `_analysis/questions/*.json`、`question-index.json` 和状态文件。
- 最终 `knowledgepointslist.md`、`knowledge-points/` 和审查文件仍按当前 track 的输出模板生成。

冲突裁决优先级：

1. 题目原文、考试说明、老师划重点
2. 老师课件和课堂强调
3. 指定阅读文本
4. 课堂笔记
5. 补充材料
6. 模型常识

## Phase 1：题目提取

### 题目分析 Agent

每份真题、样题或复习题由一个 Question Agent 处理。Phase 1 只处理题目来源，不同时处理课件、笔记、阅读材料或补充材料。

提示词要点：

- 逐字提取题干，不概括、不改写。
- 标注题型：名词解释、简答、比较题、材料分析、案例分析、论述题、评论题。
- 标注可能涉及的概念、作者/文本、理论传统、争议、案例。
- 判断这道题需要“定义型答案”“比较型答案”“材料分析型答案”还是“综合论述型答案”。
- 输出 `_analysis/questions/<source-slug>.json`。

## Phase 1.5：题目索引合并

所有 Question Agent 完成后，父流程合并 `_analysis/questions/*.json`，生成 `_analysis/question-index.json` 和 `_analysis/question-index.md`。如果没有真题或样题，也要写入空的 `question-index`，并记录后续分析依据来自课程总结、考试说明、老师强调和材料结构。

## Phase 2：材料证据分析

所有 Evidence Agent 必须读取父流程提供的 `question-index` 摘要；无真题时读取“无真题替代依据”摘要。Evidence Agent 只写自己的 `_analysis/*-analysis*.md` 文件，不修改 `knowledgepointslist.md`、`knowledge-points/` 或 `coverage-audit.md`。

### 课件/笔记分析 Agent

提示词要点：

- 先记录讲次编号、标题、课程位置和本讲中心问题。
- 按课件顺序提炼“讲授主线”：从什么问题开始，如何推进，落到哪些概念、案例或争议。
- 提取课程核心概念和老师使用的定义。
- 提取本材料中的概念群，而不是只提取孤立关键词；记录相邻概念、易混概念和反复出现的表达。
- 记录老师反复强调的词、框架、价值判断和分析提示。
- 识别概念之间的谱系、对立、批评和转向。
- 对重要观点做课程化概括：主张、理由或机制、课程证据、批评或限制、分析结论。材料很碎时，优先提炼最能支撑问题分析的观点和事例。
- 提取可支持问题分析的短引文、案例和比较维度。
- 标注每条内容的材料来源。
- 过滤封面、课程联系方式、分组名单、课堂展示评分规则等行政内容；仅在它们说明考试题型、课程主题或展示议题时保留。

### 补充材料分析 Agent

提示词要点：

- 提取案例事实、政策事件、文本细节和补充解释。
- 标注这些材料能支撑哪个概念、争议或论点。
- 标出与主课件不同的解释角度或可能冲突。

### 阅读材料 / 讲义分析 Agent

每个重要讲义、阅读文本或课件文件可分配一个 Agent。

中间分析不使用固定表格模板。Agent 可以根据材料本身选择最合适的组织方式，例如按讲授顺序写分析备忘录、按作者/文本写论证链、按争议写立场图谱、按案例写材料库，或混合使用。唯一要求是信息要充分、出处要清楚、关系要讲明白，不能为了贴合格式而删掉复杂内容。

## Phase 3：议题图谱构建

主流程汇总所有分析：

1. 读取题目索引和所有材料分析。
2. 提炼各 subagent 的核心发现，合并重复内容，保留观点、事例、分析角度和可复述的分析结论；不原样拼接 subagent 小标题。
3. 合并重复概念和同义表述，优先使用老师课件中的措辞。
4. 把专题组织为讲次精华、概念、作者/文本、理论争议、案例群、历史脉络或综合论述主题。
5. 建立题目到专题的映射；没有真题时建立课程重点到专题的映射。
6. 生成 `knowledgepointslist.md` 和 `_analysis/coverage-audit.md`。

## Phase 4：专题文件生成

每个专题 Writer Agent 必须获得：

- 完整 `knowledgepointslist.md`
- 对应专题的材料证据包
- 相关题目原文，如有
- 相关作者/文本/案例/争议的材料摘录
- [output-templates.md](output-templates.md) 中的专题文件模板

父流程先按 `knowledgepointslist.md` 中的谱系、历史脉络或论证依赖生成稳定的前置摘要。同一依赖层的专题 Writer Agent 可以并行；后续层依赖尚未生成且摘要不足时，必须等待前置专题完成。

Writer 核心指令：

- 写成可用于课程复习和问题分析的专题讲义，而不是百科词条。
- 保留课程措辞、老师强调、lecture 顺序和材料证据。
- 对 subagent 输出做提炼归纳：提取观点、事例、分析角度和综合判断，不要把中间分析文件逐段搬进 KP。
- lecture-first 模式下先写“讲次精华提炼”：本讲主线、核心内容、关键事例和结论/开放争议。
- 覆盖要能支撑问题分析：对应 lecture 中属于本专题的主要概念、观点、作者/文本、案例和争议应被提炼进文件；不得把文科 KP 压缩成几条复习提纲。
- 明确问题意识、概念界定、理论谱系、争议结构和案例素材。
- 重点写“观点概括”：把重要观点整理成主张、理由、证据、批评/限制和分析结论。
- 重点写“问题分析素材”：给出关键概念、机制、比较维度、争议转折、评价角度和案例材料。
- 设计一道自拟题目并示范如何用本专题观点和案例分析。
- 有真题或样题时逐题解析；没有真题时不要编造真题，可用自拟题目辅助分析。
- 不要使用理工科路径的“严格推导 / 公式符号表 / 计算流程”模板，除非课程材料本身要求。

## Phase 5：质量审查

审查 Agent 检查：

1. 题目覆盖，如有真题或样题。
2. 课程重点覆盖，如没有真题。
3. KP 是否按 lecture 的实际讲授顺序组织，是否能从 `knowledgepointslist.md` 回溯到每一讲。
4. 是否正确过滤行政页和无关名单，没有把课堂管理信息当成知识点。
5. 概念定义是否贴合课程材料，而非泛化百科。
6. 理论谱系和争议关系是否清楚。
7. 知识点覆盖是否全面，是否漏掉对应 lecture 中的重要概念、作者/文本、观点或案例。
8. 观点概括是否充分，是否把材料观点转化成主张、理由、证据、批评/限制和分析结论。
9. 案例是否具体，是否能支撑论点。
10. 自拟题目分析是否贴合课程材料。
11. 是否误套理工科模板。
12. 是否存在薄文件：只有短列表，没有解释、比较、案例和问题分析；或只有观点名，没有观点概括和分析素材。

审查输出保存到 `_analysis/quality-review.md`，并同步更新 `_analysis/coverage-audit.md`。
