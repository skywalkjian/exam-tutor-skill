## 目标学习者

- 时间紧迫，需要准备以概念辨析、理论谱系、文本理解、案例分析、材料分析、简答题和论述题为核心的大学考试。
- 可能不缺“逻辑”，而是缺少课程话语、作者立场、争议结构、材料证据和围绕问题展开分析的能力。
- 目标是形成可复述、可分析、可迁移、贴合老师材料的课程理解，而不是把课程改造成公式化答题流程。

## 人文社科核心原则

- 课程材料的概念、作者、案例、文本、课堂措辞和考试说明优先于通用百科式知识。
- 如果 `materials/lectures/` 中的课件、讲义或课程总结质量较高，进入 **lecture-first 模式**：直接从 lecture 中提取精华并提炼成 KP，主要按照 lecture 的讲授顺序组织，不先套外部理论框架，也不把课程改写成百科综述。
- lecture-first 模式下，KP 的任务是“帮学生复述老师这门课怎么讲”，而不是“把网上同名主题讲全”。每个 KP 应保留讲次逻辑：本讲要回答的问题、核心概念、老师给出的观点、关键案例、争议和可复述的分析结论。
- 过滤行政性内容：课程信息、分组名单、展示评分规则、课堂提醒、重复封面页等，除非它们直接说明考试题型、展示题目或老师明确要求。
- 真题和样题仍然重要，但如果没有真题，不得编造题目；应转向课程总结、考试题型说明、老师强调和材料结构。
- 知识点不是“公式 / 定理 / 解题流程”的容器，而是“问题意识 / 概念界定 / 理论谱系 / 争议结构 / 文本证据 / 案例素材 / 问题分析”的组合。
- 人文社科 KP 不能只是提纲。每个 KP 应像一份可闭卷复述的专题讲义：提炼对应 lecture 中的主要概念、作者/文本、观点、案例和可迁移论证句；不要求机械填满所有理论背景。
- 文科考试通常要求“知道关键观点”和“能用材料分析”。生成 KP 时优先做两件事：
  - **lecture 精华提炼**：把对应 lecture 的核心问题、概念群、作者文本、关键事例和主要争议收拢成可复述的主线；但不要用课件外知识冲淡老师的讲授重点。
  - **观点概括**：把 lecture 中的重要观点概括为“主张 - 理由/证据 - 批评或限制 - 分析结论”，避免只堆材料摘录。
- 不强制写“严格推导”“公式符号表”“计算流程”。除非课程材料本身要求，否则不要使用理工科模板标题。
- 重点训练学生围绕问题展开分析：解释概念、比较观点、组织论证、引用材料、分析案例、回应争议。
- Mermaid 图用于理论谱系、概念关系、立场对比、历史脉络、案例归类和答题结构。
- 如果材料只有摘录而没有清楚的论证判断、比较维度和例证，视为深度不足。

## 执行阶段

阶段顺序由公共 [../../runtime/phase-barrier.md](../../runtime/phase-barrier.md) 控制；本路径只定义人文社科内容要求。

### Phase 0. 材料关卡

- 扫描 `materials/` 下所有课程材料。
- 优先级：考试说明/课程总结/老师划重点 > 历年真题或样题 > 课件/讲义 > 课堂笔记 > 阅读文本 > 补充材料。
- 没有真实课程材料时停止，不生成泛化议论文素材。

### Phase 1. 题目提取

- 如果存在历年真题、样题或复习题，逐字提取题干，保存到 `_analysis/questions/*.json`。
- 题型分类建议包括：名词解释、简答、比较题、材料分析、案例分析、论述题、评论题。
- 标注每题可能涉及的概念、作者/文本、理论传统、案例和争议。
- 如果没有真题，`question-index.json` 保持空数组，并在后续审计中说明“无真题，依据课程材料和考试说明推断重点”。

### Phase 1.5. 题目索引合并

- 合并 `_analysis/questions/*.json` 为 `_analysis/question-index.json`。
- 生成 `_analysis/question-index.md`，便于人工检查是否漏题或误提。
- 后续所有题目引用都以该索引为准。

### Phase 2. 材料证据分析

提取重点不是“知识点名称清单”，而是考试可用材料信息。下面是分析目标，不是 Evidence Agent 中间文件的固定输出格式；中间分析可以按材料本身组织，避免为了贴合表格或字段而丢失复杂内容。

- lecture 顺序、讲次标题、每讲的中心问题和讲授转折
- 核心概念及课程定义
- 该概念所属的概念群、近义词、反义词、易混概念和课程中出现的相邻议题
- 概念出现的问题背景
- 作者、学派、理论传统和相互关系
- 重要观点的概括：主张、理由、证据、批评、局限、可复述的分析结论
- 争议双方或多方的主张、前提、批评点
- 老师反复使用的关键词、框架和评价语
- 可支持分析的材料证据、短引文、案例、政策/事件/文本细节
- 适合概念辨析、材料分析或综合讨论的组织方式
- 需要过滤或降权的内容：封面、目录、考勤、分组、展示评分、无关名单、重复页、仅作为课堂管理的信息

### Phase 3. 议题图谱

- 生成 `knowledgepointslist.md`。
- KP 可以是讲次、概念、理论争议、作者/文本、案例群、历史脉络或综合论述主题。
- lecture-first 模式下，默认一讲对应一个 KP；若两讲明显是同一主题的连续部分，可以合并为一个 KP，并在标题和材料证据中标明覆盖的讲次。不要为了凑少量大专题而打乱老师的讲授顺序。
- 主要按课程讲授顺序排列；只有在考试说明或课程总结明确要求综合时，才按概念谱系、历史脉络或论证依赖做小幅微调。
- 图谱应展示：概念关系、理论谱系、争议结构、案例归属和考试题型连接，而不只是“前置依赖”。
- 同步生成 `_analysis/coverage-audit.md`，说明题目覆盖、材料覆盖和低置信度风险。

### Phase 4. 知识点文件

每个 KP 写成一份可直接服务课程复习和问题分析的专题讲义。结构和细节以 [output-templates.md](output-templates.md) 为准；模板是写作支架，不需要每个课程都逐项填满。最低目标是把 subagent 的材料分析提炼为观点、事例、分析和可复述的判断。

- `[!tip] 学习指南`
- 课程定位和考试用途
- 材料来源与 subagent 提炼依据
- 问题意识和一句话主线
- 核心观点概括：主张、理由/证据、批评或限制、分析结论
- 概念界定和必要的比较维度
- 理论谱系、历史脉络或争议结构，如课程材料需要
- 代表事例、文本或材料分析：说明事例如何支撑观点
- 自拟题目分析：材料足够时设计一道问题，并用本 KP 的观点和案例做示范分析；材料不足时可不写
- 真题/样题解析，如有
- 常见误区和考前速记

### Phase 5. 质量审查

审查项：

- 题目覆盖完整性，如有真题
- 是否贴合课程材料和老师措辞
- 是否按 lecture 的实际逻辑顺序组织，而不是打散成模型自拟专题
- 是否过滤了行政页、分组名单、评分规则等非考试内容
- 概念界定是否清楚，是否避免百科式泛化
- 知识点覆盖是否足够支撑考试作答：对应 lecture 的主要概念、观点、作者/文本和案例是否被提炼；不得只保留少量高频词
- 观点概括是否充分：每个 lecture 的核心观点是否有主张、理由/证据、批评或限制，以及可复述的分析结论
- 理论谱系、争议结构和比较维度是否可用于写作
- 案例与材料证据是否具体，是否能支撑观点
- 自拟题目分析是否贴合材料，而不是空泛口号；如果没有自拟题目，是否有合理原因
- 是否错误套用了理工科路径的公式、推导、计算题结构
- 是否存在薄文件：只有概念罗列，没有问题意识、争议、材料证据和问题分析
- 是否存在“文科薄文件”：只有框架没有内容、只有关键词没有观点概括、只有案例名没有案例解释、只有立场没有理由和反驳。

### Phase 6. 学习计划

- 只在用户提供剩余天数或考试日期后生成 `study-plan.md`。
- 计划应围绕“能分析出来”安排：概念背诵、理论比较、案例素材、材料分析训练和综合问题练习。
- 如果没有真题，清楚标注“基于课件/课程总结/考试说明，而非历年真题”。
